# OpenDoge 多技能目标标定

本文件由 `uv run opendoge-calibrate --write` 生成。数值全部来自 MJCF 的
运动学与静力学计算，不是估计值；修改机器人模型后请重新生成。

## 1. 刚体与行程约束

- 总质量：**4.591 kg**
- 广义坐标：18（6 浮动基座 + 12 关节）
- MJCF 声明站姿基座高度：0.158 m
- 落地后实测站姿高度：0.151 m
- 髋到足可达竖直高度：**-0.0520 m → 0.1715 m**（峰值姿态 thigh=0.541, calf=-1.040）
- 站姿腿高：0.1373 m
- **从站姿可继续伸腿的行程：0.0342 m**

> 这个行程上限直接决定了原地跳跃的离地高度只能是厘米级。

## 2. 静力学校验

| 姿态 | 基座高度 | 髋力矩 | 大腿力矩 | 小腿力矩 | 峰值占额比 | 基座竖直残差 |
|---|---|---|---|---|---|---|
| 站姿（默认关节角） | 0.151 | 0.698 | 0.042 | 0.797 | 0.116 | -1.02e-12 |

基座竖直残差是浮动基座上「没有执行器却需要的力」。它接近 0 表示足端接触力
恰好承担了整机重力，因此同一姿态下的关节力矩才是真实静力矩。接触模型是软
的，所以基座高度用二分求解到该平衡点，而不是让足端刚好触地。

站姿静力矩远低于 6/6/9 Nm 限值，说明静力学链路可信：`mj_forward` 解出足端
接触力后，`mj_inverse` 在零加速度下给出的关节力矩即为所需驱动力矩。

|---|---|---|---|---|---|
| -0.640 | -1.313 | 0.301 | 0.422 | -0.041 | 0.008 |
| -0.640 | -1.450 | 0.295 | 0.416 | -0.029 | 0.008 |
| -0.436 | -1.313 | 0.289 | 0.410 | -0.071 | 0.008 |
| -0.640 | -1.587 | 0.288 | 0.409 | -0.017 | 0.008 |

上表是「带 15% 关节余量」子集里基座最高的若干项。全部可行解（峰值占额比 ≤ 0.6）的基座高度区间为 **0.018 – 0.322 m**，后足离地区间为 **0.139 – 0.443 m**。

**推荐值取该区间的中位**，而不是最高点：可行域边界上的姿态留给平衡控制器的余量最小，作为训练目标最容易卡住。

**推荐倒立目标（Step 2 使用）：**

```yaml
pitch_deg: +90
front_leg: {thigh: -0.233, calf: -2.407}
base_height_target: 0.220   # m，相对地面
rear_foot_clearance_target: 0.341   # m
projected_gravity_target: [1.000, 0.000, -0.000]
peak_effort_ratio: 0.008
```

静止倒立所需峰值力矩仅为额定的 0.76%，因为前腿此时几乎是一根与重力同向的直柱。**所以倒立的难点不是力矩，而是把倒立摆稳住**：目标姿态静态可行，训练预算应该花在平衡与噪声鲁棒性上。

## 4. 原地竖直跳的推离预算

| 量 | 值 |
|---|---|
| 站姿腿高 → 峰值腿高 | 0.1373 → 0.1715 m |
| 伸腿行程（唯一的推离窗口） | 0.0342 m |
| 四腿竖直推力（力矩约束） | 13.3 倍体重 |
| 足端最快竖直速度（`Kd=0.5` 阻尼约束） | 1.29 m/s |
| **推离窗口时长** | **26.5 ms = 2.6 个控制步** |
| 解析上界（不做设计用） | 抬升 0.119 m |

两条独立结论：

1. **力矩不是瓶颈**：四腿可输出约 13.3 倍体重的竖直推力，而整段行程只有 34.2 mm。
2. **真正的瓶颈是控制频率**：按阻尼约束的足端速度，整个推离过程只有 26.5 ms，在 100 Hz 下相当于 2.6 个控制步。策略几乎不可能在起跳过程中闭环修正，起跳必须靠 one-shot 命令 + 相位时钟预先编排。

**推荐跳跃目标（Step 2 使用）：**

```yaml
jump_type: in_place_vertical
apex_rise_target: 0.03 - 0.08   # m，相对站姿的质心抬升
landing: 落地后 1 s 内恢复站立，不摔倒
```

该区间显著低于上面的解析上界，留出控制余量；把目标定到上界附近会把问题同时变成「精确起跳时机」和「落地稳定」两件难事。

## 5. 对 Step 2 / Step 3 的约束

- 倒立：`base_height_target` 取上表推荐值，`projected_gravity` 目标取
  `[1.000, 0.000, -0.000]`（前腿支撑支路）；后足离地写成稠密奖励，避免稀疏探索。
- 跳跃：一回合只有一次起跳机会，终止条件必须排除 `base_contact`，否则
  起跳与落地会被误判为失败（Go2 Backflip 的已知坑）。
- 统一策略：walk 与 getup 的 actor 观测已是 48 维且字段顺序一致，追加
  skill block 后为 57 维，critic 72 → 81 维。
